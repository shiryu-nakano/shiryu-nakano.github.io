    まとめ

    ⏺ Hugo + Org-mode での画像貼り付け設定まとめ

    概要

    Emacsでorg-modeを使いながら、画像を貼り付けてEmacsとHugo両方で表示できるようにする設定です。

    ディレクトリ構造

    shiryu-nakano.github.io/ ├── content/ │ └── posts/research/ │ └── org-test.org ← orgファイル ├── static/ │ └── images/ │ └── posts/research/ │ └── 20260419_123420.png ← 画像はここに保存 └── layouts/ └── posts/ └── single.html ← パス変換用

    変更したファイル

    1. ~/.emacs.d/init.el

    画像貼り付け時に:

    • Hugoサイト内: static/images/ に保存、相対パスで参照
    • それ以外（org-roam等）: 従来通り ファイル名_image/ に保存

    (with-eval-after-load "org" (defun org-insert-clipboard-image () (interactive) (let* ((hugo-root (locate-dominating-file default-directory "hugo.toml"))) (if hugo-root ;; Hugoサイト内 → static/images/に保存、相対パスで参照 (let* ((content-dir (expand-file-name "content" hugo-root)) (current-dir (file-name-directory (buffer-file-name))) (relative-path (if (string-prefix-p content-dir current-dir) (file-relative-name current-dir content-dir) "")) (image-dir (expand-file-name (concat "static/images/" relative-path) hugo-root)) (image-name (format-time-string "%Y%m%d_%H%M%S.png")) (image-file (concat image-dir image-name)) (org-link (file-relative-name image-file current-dir))) (make-directory image-dir t) (shell-command (concat "pngpaste " image-file)) (when (file-exists-p image-file) (insert (format "#+ATTR_ORG: :width %d\n" 40)) (insert (concat "" org-link ""))) (org-display-inline-images)) ;; Hugoサイト外 → 従来通り …))))

    1. layouts/posts/single.html

    go-orgが生成するHTMLの画像パスを変換:

    {{ define "main" }} <article class="markdown book-post"> … <div class="book-post-content markdown-inner"> {{- .Content | replaceRE `src="../../../static` `src="` | safeHTML -}} </div> </article> {{ end }}

    1. .github/workflows/pages-deploy.yml

    Jekyll → Hugo に変更:

    • name: Setup Hugo uses: peaceiris/actions-hugo@v3 with: hugo-version: 'latest' extended: true
    • name: Build site run: hugo –minify –baseURL "${{ steps.pages.outputs.base_url }}/"

    動作の流れ

    1. Emacsで C-x C-y で画像貼り付け ↓
    2. 画像が static/images/posts/research/xxx.png に保存 ↓
    3. orgファイルに が挿入 ↓
    4. Emacs: 相対パスで画像を表示 ✓ ↓
    5. Hugo: layouts/posts/single.html の replaceRE でパス変換 → <img src="/images/posts/research/xxx.png"> ✓

    結果 ┌───────────────────┬────────────────────┐ │ 環境 │ 画像表示 │ ├───────────────────┼────────────────────┤ │ Emacs │ ✓ 相対パスで表示 │ ├───────────────────┼────────────────────┤ │ Hugo (ローカル) │ ✓ replaceRE で変換 │ ├───────────────────┼────────────────────┤ │ GitHub Pages │ ✓ 同上 │ ├───────────────────┼────────────────────┤ │ org-roam (Hugo外) │ ✓ 従来通り動作 │ └───────────────────┴────────────────────┘

    • 書くことによって考える 考えごとがうまくいかない時の考え方の変え方 考え事がたくさんある

      • 自分では変えられない外的要因などの問題を抱えているとき 人間関係，環境の変化
      • 解決したい問題があるとき 互いに排反ではないかもしれないが，このような場合に頭を整理したくなるときがある． しかし，「考え事」を始めたにも関わらず思考が発散し，誰かが答えを書いていることに期待してネットサーフィンを 開始して数時間溶かしてしまうことがあった．
      • こういうことをなくしたい． 発散的な思考は無意味ではない．クリエイティビティはむしろ発散的思考の産物と捉えることができたりもする・ 現実的な時間で，現実的に解決や妥結に達したい時に，この頭の使い方を始めると大抵うまくいかない．
      • 何が問題か？ → 問い方に問題があるから ①解決できない（or 一般的に難しい問題）であるとき→これは普通に難しいのでこのパターンは除外する． 難しい問題は他の人も難しいし，たくさんの人がぶち当たっている問題である可能性が高いので，まずそれに気づく． 小さく分割して解決に近づく． ②考えかたが悪い． 解決したい問題に対して，まず自分が「解決した」と結論づけられる条件が定まっていないのに 何か悶々と考えていても，基本的にネットサーフィンが始まる まず何が解決なのか，範囲を決める．その範囲を決める諸条件は基本的には外的要因を考慮すればいい． 外的要因によって定まる領域の外側にはどう頑張ってもいけない．（1日は24時間しかない，とか自分の能力とか，お金の問題とか） ここが定まると，あとは自分がどこからどこまでなら妥協できるかを決めるだけ．
